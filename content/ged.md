当我们谈论代码编辑器时，脑海里通常会出现两类工具：一类是功能完整、插件丰富的桌面 IDE，另一类是高度可定制、需要长期打磨配置的终端编辑器。

`ged` 想探索的是中间的空间：它足够轻，可以从终端立即启动；也足够完整，可以浏览项目、修改文件、搜索代码、运行命令，并通过语言服务器获得真正理解代码的智能提示。

它是一个使用 Go 编写、基于 [Star](https://github.com/23jdd/Star) 构建的 TUI 编辑器。


## 为什么再做一个终端编辑器？

这个项目最初关注的并不是“替代 Vim 或 VS Code”，而是几个更具体的问题：

- 能不能只用一个二进制文件打开目录并开始工作？
- 能不能让只读浏览与实际写入有明确的边界，减少误操作？
- 能不能保留 TUI 的速度，同时拥有补全、诊断、文档和自动导包？
- 能不能让命令输出、帮助信息和补全文档在有限的终端空间中仍然完整可读？

`ged` 的设计围绕这些问题展开。它没有隐藏这些能力，而是把文件、模式、命令和语言服务器状态直接呈现在界面上。

## R/W 双模式：先阅读，再写入

打开 `ged` 后，编辑器默认处于 `R READ` 模式。此时可以移动光标、浏览文件、搜索内容、执行命令，但普通按键不会修改文件。

按 `i` 进入 `W WRITE` 模式后，输入、删除、换行和接受补全才会真正修改缓冲区；按 `Esc` 则返回只读模式。

```text
R READ  --按 i-->  W WRITE  --按 Esc-->  R READ
```

这个模型很简单，却能让“我正在看代码”和“我正在改代码”成为两种清晰的状态。冒号也遵循这一规则：在只读模式中，`:` 打开命令行；在写入模式中，它只是写入文件的普通字符。

## 从目录开始，而不是从单个文本框开始

`ged` 可以打开当前目录、指定目录，也可以直接打开一个文件：

```bash
ged
ged ./my-project
ged ./my-project/main.go
```

左侧文件树展示工作区内容，并支持鼠标选择。除了逐层寻找文件，也可以按 `Ctrl+O` 输入部分文件名进行模糊搜索；按 `Ctrl+F` 则搜索整个工作区的文件内容。

常用导航操作包括：

| 操作 | 快捷键 |
| --- | --- |
| 文件名搜索 | `Ctrl+O` |
| 工作区内容搜索 | `Ctrl+F` |
| 跳转到指定行 | `Ctrl+G` |
| 聚焦或离开文件树 | `Ctrl+B` |
| 打开命令面板 | `Ctrl+P` |
| 保存 | `Ctrl+S` |

搜索、文件树与编辑区都在同一个终端界面内完成，不需要离开编辑器组织上下文。

## 不只是文本补全：真正接入语言服务器

关键字列表只能告诉编辑器 `func` 或 `struct` 存在，却无法理解项目中的自定义类型、函数签名和包关系。为此，`ged` 实现了标准 JSON-RPC/LSP 客户端。

当前可以自动检测以下语言服务器：

- Go：`gopls`
- Rust：`rust-analyzer`
- Python：`pyright-langserver --stdio` 或 `pylsp`
- JavaScript/TypeScript：`typescript-language-server --stdio`
- C/C++：`clangd`

按 `Ctrl+L` 可以启动或停止当前文件对应的语言服务器，按 `Ctrl+Space` 主动请求补全。输入 `.` 时会自动触发成员提示；Rust 和 C++ 输入 `::` 时也会触发路径补全。

补全并不止显示一个名称。选中候选项后，`ged` 会通过 `completionItem/resolve` 按需加载完整签名、详情和文档，避免启动时一次性请求大量无用内容。文档较长时，可以使用 `PageUp`、`PageDown` 或鼠标滚轮继续阅读。

当语言服务器返回 `additionalTextEdits` 时，接受候选还会同时写入 Go 的 `import` 或 Rust 的 `use`。也就是说，选择一个尚未导入的包符号，可以同时完成代码补全与自动导包。

## 语言服务器还没准备好，也能给出提示

LSP 启动和索引项目需要时间，因此 `ged` 还提供了一层本地补全：

- 当前语言的关键字；
- 当前缓冲区中的标识符；
- 工作区中的自定义函数、类型、结构体、变量和常量。

例如，在 Go 文件里输入 `fu` 可以立即看到 `func`；在 Rust 文件里输入 `ma` 可以看到 `match`。当 `gopls` 或 `rust-analyzer` 返回结果后，LSP 候选会与本地候选合并。

本地提示让输入保持即时，语言服务器则补上语义理解。两者不是互相替代，而是解决不同阶段的问题。

## 在编辑器里运行命令

只读模式下按 `:` 可以使用类似 Vim 的命令行：

```text
:w                 保存
:q                 退出
:q!                放弃未保存修改并退出
:wq                保存并退出
:e PATH            打开文件
:cd DIR            切换工作区
:find TEXT         搜索工作区内容
:goto 42           跳转到第 42 行
:lsp               自动启动或停止语言服务器
:format            格式化当前文件
:refresh           刷新文件树
:!go test ./...    在工作区执行 shell 命令
:help              查看帮助
```

Shell 命令的标准输出和错误信息会显示在浮动窗口中。输出过长时不会直接截断：长行会根据窗口宽度自动换行，并支持方向键、`PageUp`、`PageDown`、`Home`、`End` 和鼠标滚轮滚动。窗口标题会显示当前位置，例如 `21-38/96`。

这让编译、测试和查看工具输出形成一个短反馈环：编辑、保存、运行、阅读结果，都不需要切换界面。

## 语法高亮与 Unicode

即使没有语言服务器，`ged` 也能对常见语言的关键字、字符串、数字和注释进行内置高亮。界面包含行号、当前行、诊断信息、状态栏、文件树以及浮动命令窗口。

终端字符并不总是“一字符一格”。中文、组合字符和宽字符都会影响光标位置与绘制。`ged` 使用 grapheme cluster 和显示宽度计算文本布局，让 Unicode 文件名、搜索词和编辑内容可以正常显示，同时避免光标覆盖或改写当前位置的原字符。

## 安装和运行

项目要求 Go，语言服务器是可选依赖。克隆源码后可以直接运行：

```bash
git clone https://github.com/23jdd/ged.git
cd ged
go run .
```

在项目目录中安装：

```bash
go install .
```

`go install .` 会编译当前模块，并将 `ged`（Windows 下为 `ged.exe`）放入 `GOBIN`；如果没有设置 `GOBIN`，则放入 `GOPATH/bin`。可以用下面的命令查看目标目录：

```bash
go env GOBIN
go env GOPATH
```

也可以手动生成一个放在当前目录的程序：

```bash
go build -o ged .
```

Windows PowerShell 中可以这样运行：

```powershell
go build -o ged.exe .
.\ged.exe .
```

要获得 Go 或 Rust 的语义补全，需要先确保对应语言服务器位于 `PATH`：

```bash
# Go
go install golang.org/x/tools/gopls@latest

# Rust（安装 rustup 工具链后）
rustup component add rust-analyzer
```

## Star 在项目中扮演什么角色？

`ged` 的界面和事件循环建立在 Star 之上。编辑器本身作为一个 Model 接收键盘、鼠标、窗口尺寸、定时器以及异步命令结果，再返回新的状态和需要执行的命令；View 则根据状态绘制文件树、编辑区和浮动窗口。

这种结构把几类逻辑分开：

- 输入事件决定状态如何变化；
- 文件系统、Shell 和 LSP 以异步消息返回结果；
- 渲染层只负责把当前状态画到终端；
- 编辑器状态不依赖具体的终端帧，可以单独测试。

因此，命令执行或语言服务器通信不会迫使界面采用阻塞式流程。对于需要持续接收诊断和补全结果的 TUI 应用，这一点尤其重要。

## 当前边界与接下来的方向

`ged` 已经覆盖日常编辑的核心路径，但它仍然是一个年轻的项目。例如，完整的撤销/重做历史、更多语言的语法解析、更丰富的多文件工作流和可配置主题，仍有继续扩展的空间。

这个项目更重要的意义，也许并不是“又多了一个编辑器”，而是证明一个小型 TUI 同样可以拥有清晰的交互模型、工作区能力和现代语言服务，并且仍然保持代码结构简单、启动方式直接。

如果你喜欢终端工具、正在学习 TUI 架构，或者想看看一个编辑器如何从文本缓冲区一步步连接到 LSP，欢迎尝试 `ged`：
